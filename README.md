# 광고 레퍼런스 수집 시스템

메리츠증권 + 경쟁 증권사(미래에셋, 삼성, NH투자, KB, 신한투자, 한국투자, 키움, 토스) 광고를
Meta, Google, 네이버 브랜드검색/파워링크에서 자동 수집하고, 대시보드로 보여주는 내부 도구입니다.

이 저장소는 두 개의 프로젝트로 구성됩니다.

- **`ad-collector/`** — Playwright/Apify 기반 수집기 (Node.js, 백그라운드 실행)
- **`ad-ref/`** — 수집 결과를 보여주는 대시보드 (Next.js, 정적 export)

---

## 전체 구조

```
[ad-collector] 광고 수집 (스케줄러가 자동 실행)
      │  data/*.json 에 저장
      ▼
sync-data.js  (ad-collector/data → ad-ref/public/data 로 복사)
      │
      ▼
[ad-ref] Next.js 대시보드가 public/data 의 정적 JSON을 읽어서 화면에 표시
```

ad-ref는 `output: 'export'`(정적 export) 모드로 빌드됩니다. 서버에서 실시간으로 API를
호출하는 구조가 아니라, **수집기가 만든 JSON 파일을 그대로 읽어서 보여주는 방식**입니다.
(단, Claude 인사이트용 API 라우트 1개는 예외 — 아래 "소재/트렌드 인사이트" 참고)

## 수집 대상 및 주기

| 항목 | 방식 | 주기 |
|---|---|---|
| Meta 광고 | Playwright 키워드 검색 + Apify(2개 계정) | 주 1회 |
| Google 광고 | Playwright (Google 광고 투명성 센터) | 주 1회 |
| 네이버 브랜드검색 | Playwright 스크린샷 + 버튼 링크 파싱 | 주 1회 |
| 네이버 파워링크 | Playwright | 주 1회 |
| Meta 브랜드 순환 확인 | Apify 재조회 | 2시간마다 |
| Meta 이미지/영상 채우기 | Playwright 상세페이지 방문 | 2시간마다 |
| 코스피/코스닥/나스닥 지수 | Yahoo Finance 공개 API | 매일 09시 |

`ad-collector/scheduler.js`가 위 주기를 cron으로 관리하고, Windows 작업 스케줄러
(`AdCollectorScheduler`, 로그온 시 자동 시작)에 등록되어 있습니다.

## 소재 / 트렌드 인사이트

파워링크 주차별 변화, 소재(광고 카피) 인사이트, 검색어 트렌드-지수 상관 설명 3가지는
**Claude Code CLI**를 로컬에서 호출(`execFileSync('claude', ...)`)해서 생성합니다.
Anthropic API 키를 별도로 발급받은 게 아니라, 이 컴퓨터에 로그인된 Claude Code
계정(Pro 플랜)을 그대로 사용합니다. 생성된 텍스트는 JSON 파일로 저장해두고
대시보드는 그 파일을 읽기만 합니다 (매번 다시 생성하지 않음).

## 운영 관련 확인/결정 필요 사항 (2026-08-04 기준)

로컬 1인 사용을 넘어 팀 서버로 옮기기 전에 아래 항목들이 정리되어야 합니다.

### 1. 네이버 API 키 — 계정 소유 문제
현재 검색어 트렌드(데이터랩)용으로 쓰는 네이버 API 애플리케이션이 `ns_2024`라는
이름의 **와이즈버즈 개인/공용 계정으로 등록된 키**입니다 (`ad-ref/.env.local`,
git에는 커밋되지 않음). 이대로 계속 써도 되는지, 아니면 메리츠증권 명의로 별도
발급받아야 하는지 확인이 필요합니다.

### 2. 수집된 미디어(브검/구글 소재 등)가 팀원 개인 PC에 로컬 저장 중
현재 브랜드검색 스크린샷, 구글/메타 광고 이미지·영상 등 실제 미디어 파일은
`ad-collector/output/`, `ad-collector/data/`에 팀원 한 명의 로컬 컴퓨터에만
쌓이고 있습니다 (용량이 계속 증가 — 최근에도 2.7GB 정리한 이력 있음). 이걸
서버 스토리지로 옮길 수 있는지, 가능하다면 스토리지 용량/비용 확인이 필요합니다.

### 3. Claude CLI 기반 인사이트 — 서버 운영 시 Anthropic API 전환 필요
지금은 로컬 PC에 로그인된 개인 Claude Code 계정으로 CLI를 호출해 인사이트를
생성합니다. 이 방식은 **개인용 대화형 사용을 전제로 한 것**이라 여러 사람이
쓰는 서버에 그대로 올리기엔 적합하지 않습니다 (인증 세션을 서버에서 상시
유지해야 하는 문제, 플랜 사용량을 여러 요청이 공유하는 문제 등). 서버로 옮길
경우 **Anthropic API(사용량 기반 과금)로 전환**하는 것이 정석이며, 이를 위한
API 키 발급 및 비용 처리 방안이 필요합니다. 혹은 기존 CLI를 호출하여 인사이트를
생성하는 방법이 있다면 공유 한번만 부탁드리겠습니다.

### 4. 서버 배포 방법
현재 코드는 이 저장소(git)에 올려둔 상태이나, 실제로 팀이 접속할 수 있는
서버에 띄우는 절차는 아직 정해지지 않았습니다. 확인/결정 필요:
- 배포 대상 서버(사내 서버 vs Vercel 등 클라우드)
- `ad-ref`는 정적 export라 별도 Node 서버 없이도 정적 파일 호스팅으로 열 수 있으나,
  Claude 인사이트 API 라우트(POST)는 정적 파일만으로는 동작하지 않아 Node 서버가
  필요함 — 이 부분은 위 3번(Anthropic API 전환) 결정과 맞물림
- `ad-collector`(수집기)는 계속 특정 컴퓨터(또는 서버)에서 스케줄러로 상시 실행되어야 함

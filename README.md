# 광고 레퍼런스 수집 시스템

메리츠증권 + 경쟁 증권사(미래에셋, 삼성, NH투자, KB, 신한투자, 한국투자, 키움, 토스) 광고를
Meta, Google, 네이버 브랜드검색/파워링크에서 자동 수집하고, 대시보드로 보여주는 내부 도구입니다.

이 저장소는 두 개의 프로젝트로 구성됩니다.

- **`ad-collector/`** — Playwright/Apify 기반 수집기 (Node.js, 백그라운드 실행)
- **`ad-ref/`** — 수집 결과를 보여주는 대시보드 (Next.js, 정적 export)

---

## 전체 구조

```
[ad-collector] 광고 수집 (스케줄러가 자동 실행)
      │  ad-collector/data/*.json 에 저장
      │  (이미지·영상·스크린샷은 ad-collector/output/ 에 저장, S3 설정 시 업로드 후 로컬 삭제)
      ▼
node sync-data.js  (ad-collector/data, output → ad-ref/public/data 로 복사)
      │
      ▼
[ad-ref] Next.js 대시보드가 public/data 의 정적 JSON을 읽어서 화면에 표시
```

ad-ref는 `output: 'export'`(정적 export) 모드로 빌드됩니다. 서버에서 실시간으로 API를
호출하는 구조가 아니라, **수집기가 만든 JSON 파일을 그대로 읽어서 보여주는 방식**입니다.
(단, Claude 인사이트용 API 라우트 2개는 예외 — 아래 "인사이트는 어떻게 만들어지는가" 참고)

`sync-data.js`는 자동으로 실행되지 않습니다. 수집이 끝난 뒤 사람이(또는 별도 cron으로)
직접 `cd ad-ref && node sync-data.js`를 실행해야 대시보드에 최신 데이터가 반영됩니다.

## 수집 대상 및 주기

| 항목 | 방식 | 주기 |
|---|---|---|
| Meta 광고 (키워드 "증권") | Playwright 키워드 검색 + Apify(2개 계정) | 주 1회 |
| Google 광고 (브랜드 9개) | Playwright (Google 광고 투명성 센터) | 주 1회 |
| 네이버 브랜드검색 | Playwright 스크린샷 + 랜딩페이지 버튼 링크 파싱 | 주 1회 |
| 네이버 파워링크 (일반 키워드 "증권"/"주식") | Playwright | 주 1회 |
| 검색광고 브랜드키워드 (브랜드명 9개 자체를 키워드로) | Playwright, 브랜드×기기마다 새로고침 30회 | 주 1회 |
| Meta 브랜드 9개 순환 확인 | Apify 재조회 | 2시간마다(짝수 시) |
| Meta 이미지/영상 채우기 | Playwright 상세페이지 방문 | 2시간마다(홀수 시) |
| 코스피/코스닥/나스닥 지수 | Yahoo Finance 공개 API | 매일 09시 |
| 트렌드 리포트 (앱별 MAU/신규설치) | 구글 시트 연동 | 매일 09시 30분 |
| 커뮤니티 반응 (화제 키워드 + 감정분류 + 실제 반응) | 디시인사이드+에펨코리아 글 수집 + Claude 웹서치 | 매일 08시 |
| 구글 이미지 다운로드 실패분 복구 | `googleMediaBackfill.js` | 매일 07시 |
| 구글 이미지 소재 OCR 텍스트 백필 | `googleTextBackfill.js` (200건/일) | 매일 07시 30분 |

`ad-collector/scheduler.js`가 위 주기를 cron으로 관리하고, Windows 작업 스케줄러
(`AdCollectorScheduler`, 로그온 시 자동 시작)에 등록되어 있습니다.

## 데이터가 저장되는 방식

- 모든 수집 결과는 `ad-collector/data/*.json`에 저장됩니다 (광고 목록/인사이트/시세 등
  종류별로 파일이 나뉘어 있음 — 예: `index.json`, `bs_index.json`, `powerlink_index.json`,
  `powerlink_brand_index.json`, `community_trend.json` 등).
- 광고 이미지·영상·스크린샷 실물 파일은 `ad-collector/output/` 아래 저장됩니다
  (`images/meta/`, `images/google/`, `screenshots/` 등). 각 광고 데이터 항목의
  `localPath`/`localImage`/`screenshotPath` 필드가 이 상대경로를 가리킵니다.
- **S3 호환 스토리지 지원(선택)**: `ad-collector/.env`에 `S3_ENDPOINT`,
  `S3_REGION`, `S3_BUCKET`, `S3_ACCESS_KEY_ID`, `S3_SECRET_ACCESS_KEY`,
  `S3_PUBLIC_BASE_URL` 6개 값을 채우면, 수집된 미디어를 로컬 대신 S3에 업로드하고
  `localPath` 등에 공개 URL을 그대로 저장합니다(업로드 성공 시 로컬 파일은 삭제).
  6개 중 하나라도 비어있으면 지금처럼 로컬 저장 그대로 동작합니다 (`.env.example` 참고).
- 각 광고 항목이 갖는 주요 텍스트 필드: `advertiserName`(광고주명), `headline`(제목),
  `copyText`(본문 카피), `keyword`(수집 시 사용한 검색어), `landingUrl`(랜딩 URL),
  `platform`(meta/google/naver_bs 등), `status`(active/ended), `collectedAt`(수집 시각).
  단, **구글 이미지형 광고는 원본(광고 투명성 센터)이 텍스트를 아예 제공하지 않아서
  `copyText`/`headline`이 항상 비어있습니다** — 아래 "소재 인사이트" 항목 참고.
- `node sync-data.js`(ad-ref 폴더 안에서 실행)가 위 JSON과 미디어 파일을
  `ad-ref/public/data/`로 복사합니다. S3를 쓰는 경우 미디어 파일 복사는 건너뜁니다
  (이미 공개 URL이라 로컬 사본이 필요 없음).

## 대시보드 탭별 기능

- **경쟁사 대시보드 - 전체 / 메타 / 구글 / 브랜드별**: `index.json`(Meta+Google 광고)을
  플랫폼/브랜드/기간으로 필터링해서 카드 그리드로 보여줍니다. 상단 KPI(활성/신규/종료/
  즐겨찾기)와 소재 인사이트(아래 참고)가 함께 표시됩니다.
- **브랜드검색**: 네이버 브랜드검색(PC/모바일) 스크린샷과, 그 안의 버튼을 실제로 클릭해서
  받아온 랜딩페이지 스크린샷을 브랜드별로 보여줍니다.
- **검색광고 일반키워드**: "증권"/"주식" 두 키워드로 네이버 파워링크를 검색했을 때 뜨는
  광고 15개(제목/설명/서브링크/이미지형 서브링크/추가제목 포함)를 그대로 보여줍니다.
  이 탭은 **키워드 경매 특성상 우리 브랜드가 아닌 광고주도 섞여서 나오는 게 정상**입니다
  (경쟁 구도 파악용).
- **검색광고 브랜드키워드**: 9개 브랜드명 자체를 검색어로 파워링크를 검색하되, **그
  브랜드 본인이 낸 광고만** 걸러서 보여줍니다(`brandUtils.js`의 `matchesBrand`로 광고주명
  매칭 — 회사가 검색량 확보를 위해 자기 이름으로도 광고를 사는 경우가 많음). 한 번 수집할
  때 페이지를 30회 새로고침하며 그때그때 다르게 노출되는 소재를 누적해서 모으고, 30회를
  다 돌려도 하나도 안 잡히면 "광고 미집행 중"으로 표시합니다. 일부 브랜드는 검색 키워드와
  실제 광고주명이 달라서(예: NH투자증권의 MTS 앱 브랜드명이 "나무증권") `brandUtils.js`에
  별칭 매핑을 등록해둬야 합니다.
- **검색어 트렌드**: 네이버 데이터랩 검색량 추이를 브랜드별로 비교하고, 코스피/코스닥/
  나스닥 지수와 함께 보여줍니다. 조회 결과 아래에 그 추이에 대한 인사이트가 표시됩니다.
- **트렌드 리포트**: 팀이 관리하는 구글 시트(앱별 월간 MAU/신규설치 등)를 그대로 가져와
  표/그래프로 보여줍니다.
- **커뮤니티 반응**: "주식/투자 전반 화제 키워드"(시장 전체)와 "메리츠증권 화제 키워드"
  (브랜드 특정) 두 그룹을 매일 기록합니다. 고정 키워드 목록이 아니라 디시인사이드 주식
  갤러리(neostock)+에펨코리아 주식 게시판 글과 Claude 웹서치를 결합해서 그날그날 실제
  화제 키워드 TOP 15를 뽑고, 각각 감정 분류(긍정/중립/부정, 버블 색상)와 상대적 언급량
  (버블 크기)을 매깁니다. 캘린더로 과거 날짜를 골라볼 수 있고, TOP10 표에서 전일比·7일
  추이 스파크라인을 보여주며, 실제로 확인된 기사/커뮤니티 반응을 출처와 함께 보여줍니다.
  과거 이력은 이 기능 도입일(2026-08-05)부터 쌓이며, 그 이전 날짜는 디시인사이드 글
  작성일 기준으로 소급 백필한 것입니다(`backfillCommunityTrendHistory`).
- **데일리 뉴스 / 주간 인사이트**: 사이드바에 탭은 있지만 아직 구현 전(준비 중 placeholder)
  입니다.

## 인사이트는 어떻게 만들어지는가

세 종류(소재 인사이트/파워링크 인사이트/검색어 트렌드 인사이트/커뮤니티 반응 인사이트
포함, 총 여러 곳)가 있고, 전부 같은 규칙을 씁니다.

1. **호출 방식**: `ad-collector/insightClient.js`의 `generateInsight()`가
   `execFileSync('claude', ['-p', prompt, ...])`로 **로컬에 설치된 Claude Code CLI**를
   비대화형으로 호출합니다. 별도 Anthropic API 키가 아니라 이 컴퓨터에 로그인된 Claude
   Code 계정(구독)을 그대로 씁니다. `--allowedTools WebSearch`를 붙여서 웹 검색이 필요한
   프롬프트(커뮤니티 반응 화제 키워드 조사 등)도 처리할 수 있습니다 - Read(로컬 이미지
   읽기)는 기본 허용이지만 WebSearch는 명시적으로 허용해야 동작합니다. `generateInsight(prompt,
   data, {timeout})`로 호출별 타임아웃을 늘릴 수 있고(웹서치 포함 조사는 기본 3분→5분으로
   늘려둠), 이는 인터랙티브 세션과 사용량을 공유하므로 너무 자주/크게 호출하면 한도에
   영향 줄 수 있습니다.
2. **포맷 규칙**: 모든 인사이트 프롬프트는 `buildInsightPrompt()`로 감싸서, "첫 줄 = 한 문장
   요약, 그 아래 `- `로 시작하는 핵심 포인트 3~5개"로만 답하도록 강제합니다. 대시보드의
   `InsightBox` 컴포넌트가 이 포맷을 파싱해서 굵은 요약 + 불릿 리스트로 렌더링합니다.
   분석할 소재가 부족하면 다른 말 없이 정확히 "인사이트 없음"이라고만 답하게 되어 있고,
   호출 전에 소재 개수가 3개 미만이면 아예 Claude를 호출하지 않고 바로 그 문구로 저장합니다
   (비용 절감).
3. **생성 시점 - 두 가지 방식이 섞여 있음**:
   - **수집 시점에 미리 생성 → JSON에 저장** (파워링크 일반/브랜드키워드 인사이트,
     커뮤니티 반응 인사이트): `collector.js`/`scheduler.js`가 수집 직후 자동으로 호출하고,
     결과 텍스트를 `data/*.json`에 저장해둡니다. 대시보드는 이 저장된 텍스트를 그냥
     보여주기만 합니다.
   - **화면에서 버튼을 눌러 그때그때 생성** (경쟁사 대시보드 '전체' 탭의 소재 인사이트,
     검색어 트렌드 인사이트): 사용자가 지금 화면에 필터링된 조건(브랜드/기간/매체 등)
     그대로 보내면, `ad-ref/src/app/api/creative-insight/route.ts` 같은 API 라우트가
     그 조건에 맞는 데이터만 다시 샘플링해서 매번 새로 생성합니다. 이 라우트가 정적
     export로 안 되고 실제 Node 서버가 필요한 유일한 부분입니다.
4. **텍스트가 없는 소재(주로 구글 이미지 광고)는 이미지를 직접 읽게 함**: 구글 광고
   투명성 센터는 이미지형 소재에 카피 텍스트를 전혀 안 주기 때문에, `copyText`/`headline`이
   비어있으면서 이미지가 있는 항목은 로컬 이미지 파일 경로를 프롬프트에 같이 넘겨서 Claude가
   직접 열어보고 읽게 합니다. 다만 **한 번 호출에 최대 6장까지만** 보내기 때문에, 소재가
   수백~수천 건인 브랜드는 매번 극히 일부만 보고 인사이트를 만드는 한계가 있습니다
   (근본 해결은 수집 시점에 이미지 텍스트를 한 번 OCR로 뽑아 `copyText`에 영구 저장해두는
   것 — 아직 미구현, 필요시 요청해주세요).

⚠️ **서버 운영 시 주의**: `execFileSync('claude', ...)` 방식은 이 컴퓨터에 로그인된
개인 Claude Code 세션을 그대로 쓰는 것이라, 로그인 세션이 없는 서버에서는 그대로 동작하지
않습니다. 서버 배포 방법은 별도로 안내드립니다.

## 최근 진행 상황 (2026-08-05 기준)

이전 핸드오프(2026-08-04) 이후 진행된 내용과 아직 안 끝난 것들입니다.

### 완료된 것
- **S3 스토리지 업로드** (`ad-collector/storage.js`) - 위 "데이터가 저장되는 방식" 참고
- **다크/라이트 테마 토글** - `ad-ref/src/app/globals.css`에 CSS 변수로 색상 정의,
  `ThemeProvider.tsx`/`ThemeToggle.tsx`로 전환(사이드바 상단 버튼), 라이트 모드는 메리츠
  CI 빨강 계열(`#e6483f`)을 포인트 컬러로 사용. 컴포넌트 전반의 하드코딩 hex 색상을 변수로
  교체했으나 완벽히 100%는 아닐 수 있음 - 이상한 색이 보이면 해당 컴포넌트에 남은 하드코딩
  hex를 찾아 `var(--...)`로 바꾸면 됨.
- **구글 이미지 소재 OCR 백필** (`googleTextBackfill.js`) - 구글 이미지형 광고는 원본이
  카피 텍스트를 안 줘서, 로컬 이미지를 Claude가 직접 읽어 `copyText`에 채워 넣음. 매일
  200건씩 자동 처리(scheduler.js). 그 전 단계로 원래 다운로드 자체가 실패해서
  `localPath`가 비어있던 항목(1,092건, 주로 메리츠 - 원인은 최초 수집 시 레이트리밋
  추정)을 복구하는 `googleMediaBackfill.js`도 매일 자동 재시도됨.
- **커뮤니티 반응 탭 전면 개편** - 위 "대시보드 탭별 기능" 참고. 고정 키워드 → 실시간 화제
  키워드, 감정분류, 캘린더, TOP10+스파크라인, 실제 반응 인용까지 추가됨.
- **⚠️ Meta 소재 이미지/문구 불일치 핵심 버그 수정** - `metaAdDetail.js`가 개별 광고 이미지를
  가져올 때 쓰던 `facebook.com/ads/library/?id=...` 페이지가 실제로는 광고 1건이 아니라
  ~16개 결과 목록을 보여줘서, 캐러셀이 아닌 완전히 다른 광고의 이미지가 섞여 저장되는
  버그가 있었음(저장된 39건 중 30건, 77%가 잘못된 이미지였음 - 확인 후 전부 재검증/수정
  완료). 페이지에 표시되는 "라이브러리 ID: {id}" 텍스트로 정확한 광고 범위를 찾는 방식으로
  수정. `meta.js`(키워드 스크래퍼)의 adId/원본링크 추출도 페이스북 DOM 변경으로 죽어있던 걸
  같은 방식으로 수정.

### 아직 안 끝난 것 (다음 세션에서 이어서 할 것)
1. **Meta 키워드 스크래퍼(`meta.js`)의 광고주명 추출도 깨져있음** - 위 버그 수정 중 발견.
   현재 페이스북 DOM에서 실제 광고 카드의 광고주명을 못 뽑아내서, 진짜 광고 카드가 전부
   필터에 걸러지고 페이지 잡음(UI 아이콘 등)만 "삼성증권" 같은 검색어 브랜드명을 뒤집어쓰고
   통과하는 상태. 저장된 Meta 데이터의 89%는 Apify 경로라 영향은 작지만(44건 중 5건만
   이 경로), 정확한 수정이 필요함.
2. **브랜드별 Meta 광고 미수집 문제(근본 원인 미확정)** - 삼성증권 기준 페이스북에 실제
   게재 중인 광고 17개인데 저장된 건 5개뿐. Apify 호출 자체가 덜 가져오는 건지
   `apifyMetaClient.js`의 `matchesBrand` 필터가 걸러내는 건지 확인 필요 - 라이브 Apify
   호출(비용 발생)로 검증해야 함.
3. **구글 광고 마지막 게재일(`adLastShownAt`) 미수집** - 구글 광고 투명성 센터 원본엔
   "마지막 게재일"이 표시되는데 우리 `google.js`는 이 필드를 안 뽑고 있음. `google.js`에
   파싱 추가 필요.
4. **메리츠 등 이미지뿐인 브랜드의 소재 인사이트 근본 해결** - OCR 백필이 끝나면 대부분
   해결되지만, 하루 200건씩이라 전체가 채워지는 데 며칠 걸림.
5. **서버 인증(claude setup-token)** - 아직 미적용. 서버 결정되면 `claude setup-token`으로
   발급받은 토큰을 서버 환경변수(`CLAUDE_CODE_OAUTH_TOKEN`)로 넣어주면 코드 변경 없이
   지금 방식 그대로 서버에서 동작함 (팀 공용 계정으로 발급 권장 - 특정 개인 계정에 서버
   운영이 종속되지 않도록).

## 운영 관련 확인/결정 필요 사항 (2026-08-04 기준)

로컬 1인 사용을 넘어 팀 서버로 옮기기 전에 아래 항목들이 정리되어야 합니다.

### 1. 수집된 미디어(브검/구글 소재 등) 저장 위치
~~현재 팀원 개인 PC에만 로컬 저장 중~~ → **S3 호환 스토리지 업로드 기능을 추가해뒀습니다**
(`ad-collector/storage.js`). `ad-collector/.env`에 실제 S3 접속 정보 6개
(`S3_ENDPOINT`/`S3_REGION`/`S3_BUCKET`/`S3_ACCESS_KEY_ID`/`S3_SECRET_ACCESS_KEY`/
`S3_PUBLIC_BASE_URL`, `.env.example` 참고)만 채워주시면 이후 수집분부터 자동으로
S3에 업로드되고 로컬에는 안 쌓입니다. 실제 스토리지 계정/버킷 발급만 확인해주시면 됩니다.

### 2. Claude CLI 기반 인사이트 — 서버 운영 시 전환 필요
지금은 로컬 PC에 로그인된 개인 Claude Code 계정으로 CLI를 호출해 인사이트를
생성합니다. 이 방식은 **개인용 대화형 사용을 전제로 한 것**이라 여러 사람이
쓰는 서버에 그대로 올리기엔 적합하지 않습니다 (인증 세션을 서버에서 상시
유지해야 하는 문제, 플랜 사용량을 여러 요청이 공유하는 문제 등). 진행 방법은
별도로 안내드리겠습니다.

### 3. 서버 배포 방법
현재 코드는 이 저장소(git)에 올려둔 상태이나, 실제로 팀이 접속할 수 있는
서버에 띄우는 절차는 아직 정해지지 않았습니다. 확인/결정 필요:
- 배포 대상 서버(사내 서버 사용 필요)
- `ad-ref`는 정적 export라 별도 Node 서버 없이도 정적 파일 호스팅으로 열 수 있으나,
  Claude 인사이트 API 라우트(POST)는 정적 파일만으로는 동작하지 않아 Node 서버가
  필요함 — 이 부분은 위 3번 결정과 맞물림
- `ad-collector`(수집기)는 계속 특정 컴퓨터(또는 서버)에서 스케줄러로 상시 실행되어야 함
- `sync-data.js`는 자동 실행되지 않으므로, 수집 후 자동으로 돌게 하려면 서버 cron에
  별도 등록 필요
